# Experiment 2: Preliminary Causal TabICL Ideas

This note records the current method pool for experiment2. These ideas are
preliminary possibilities, not final design choices. The shared theme is:
inject causal information into TabICL during training or context construction so
the model learns to rely more on stable causal variables and less on spurious,
post-treatment, or dataset-specific correlations.

## 0. Chinese Snapshot

目前的方法主线可以概括为：

1. 用因果图增强 attention：把因果结构转成 attention bias matrix `M`，在
   feature attention 或 sample attention 里加入额外偏置。
2. 用因果信息做辅助任务：预训练时除了预测 `y_test`，还让模型预测变量是否是
   `Y` 的父节点、是否是 `Y` 的后果变量、变量间是否有因果路径、特征因果权重
   `w_i` 等。
3. 用因果 dropout / mask 做数据增强：训练时更常 mask 后果变量，更少 mask
   `Y` 的直接原因，扰动非因果或不稳定变量，保留关键父节点组合。
4. 保持推理接口尽量不变：优先考虑“训练时用因果信息，推理时不需要用户提供因果图”
   的设计，以降低部署难度和 train/inference gap。

当前个人优先级：

```text
辅助任务 > 训练期 causal attention bias > 因果 mask/dropout > sample-level causal attention
```

## 1. Motivation

TabICL already performs strongly as a generic tabular in-context learner.
However, some OpenML-style datasets show weaker behavior when there is class
imbalance, domain shift, selection bias, rare decision regions, or unstable
feature-label correlations. Causal information may help the model distinguish:

- which features are likely direct causes of `Y`;
- which features are consequences/effects of `Y`;
- which feature pairs have direct or indirect causal paths;
- which variables are likely irrelevant, unstable, or spurious;
- which samples are similar on causally meaningful dimensions.

The causal information can come from known graphs, estimated graphs, synthetic
pretraining priors, or auxiliary labels generated during pretraining.

## 2. Feature-Level Causal Attention Bias

Standard scaled dot-product attention:

```text
Attention(Q, K, V) = softmax(QK^T / sqrt(d)) V
```

Convert a causal graph into a structured bias matrix `M` and inject it into
feature attention:

```text
Attention_causal(Q, K, V) = softmax(QK^T / sqrt(d) + lambda * M) V
```

Here:

- `M` is the causal attention-bias matrix;
- `lambda` controls how strongly the causal structure affects attention;
- `d` is the hidden dimension.

One possible definition:

```text
M_ij = +alpha    if X_i -> X_j or X_j -> X_i
M_ij = +beta     if X_i is a parent/direct cause of Y
M_ij = -gamma    if X_i is a consequence/effect of Y
M_ij = -epsilon  if X_i and X_j have no clear causal path
M_ij = 0         if the relation is uncertain
```

Intuition:

- If two variables have a direct causal edge, strengthen their interaction.
- If a variable is a direct cause or parent of `Y`, increase its predictive
  weight.
- If a variable is a consequence of `Y`, reduce its direct influence on
  predicting `Y`.
- If two variables have no obvious causal path, mildly down-weight their
  interaction.
- If the relation is uncertain, avoid forcing a causal decision.

Training-only variant:

```text
training:  softmax(QK^T / sqrt(d) + lambda * M) V
inference: softmax(QK^T / sqrt(d)) V
```

This lets the model be guided by causal structure during pretraining while
keeping the inference interface unchanged. The main risk is train/inference
mismatch, so `lambda` should probably be small, warm-started, or annealed toward
zero near the end of training.

## 3. Sample-Level Causal Attention Bias

Assign each feature a causal importance weight `w_i`, then define causal
similarity between samples `a` and `b`:

```text
S_ab = - sum_i w_i * (x_ai - x_bi)^2
```

If two samples are close on important causal features, `S_ab` becomes larger.
Then add it to sample-level attention:

```text
Attention_sample = softmax(QK^T / sqrt(d) + tau * S) V
```

Here `tau` controls the strength of sample causal similarity.

Intuition:

- Samples similar on causally important features should attend more strongly to
  each other.
- Similarity on spurious, non-causal, or effect variables should matter less.
- This may improve context selection, retrieval-like behavior, and robustness
  under distribution shift.

Possible source of `w_i`:

- known causal graph;
- whether a feature is a direct cause of `Y`;
- whether a feature is an ancestor of `Y`;
- learned or predicted auxiliary causal importance;
- synthetic prior metadata during TabICL-style pretraining.

Risk:

- Pairwise sample bias can be expensive for large contexts.
- Bad `w_i` estimates may harm attention.
- This may be better as a context-selection or data-transform method before
  modifying TabICL internals.

## 4. Causal Auxiliary Tasks

During pretraining, besides predicting `y_test`, ask the model to predict causal
metadata generated by the synthetic prior:

```text
whether a feature is a parent/direct cause of Y
whether a feature is a consequence/effect of Y
whether two features have a direct or indirect causal path
feature importance / causal weight w_i
```

Total loss:

```text
L = L_predict + eta * L_causal_aux
```

At inference time, drop the auxiliary heads and keep only the original
prediction head.

Why this is currently the most promising first direction:

- It does not require changing the deployed inference interface.
- It uses information available in synthetic pretraining, where the causal graph
  or generating mechanism can be known.
- It encourages internal representations to encode causal role information.
- It has a smaller train/inference gap than requiring causal graphs during
  deployment.

Possible heads:

- feature-level binary head: parent/direct cause of `Y`;
- feature-level binary head: consequence/effect of `Y`;
- pairwise head: causal path exists between `X_i` and `X_j`;
- feature-level regression head: causal weight `w_i`.

Open questions:

- Which auxiliary labels can be reliably extracted from the current prior?
- Should heads attach to column embeddings, row embeddings, or final ICL states?
- Should `eta` be constant, warmed up, or annealed?
- Should auxiliary tasks be active for the full run or only early/mid training?

## 5. Causal Dropout / Causal Mask Augmentation

During training, intentionally mask or perturb variables according to causal
role:

```text
mask consequences/effects of Y more often
mask direct causes of Y less often
perturb non-causal or unstable variables more often
preserve parent/direct-cause feature groups
```

Intuition:

- Force the model to rely more on stable causal predictors.
- Reduce dependence on effects of the label or spurious correlates.
- Improve robustness without requiring causal graphs at inference.

This is a relatively stable and low-risk experimental branch because it can be
implemented in the data pipeline rather than in attention internals.

Possible variants:

- role-dependent feature masking;
- group-preserving masking for parent sets of `Y`;
- stronger perturbation on non-causal variables;
- counterfactual-style augmentation where non-causal variables change while
  parent variables are preserved.

## 6. Implementation Priority

Initial implementation ranking:

1. Causal auxiliary tasks.
2. Training-time feature causal attention bias with inference disabled.
3. Causal dropout / causal mask augmentation.
4. Sample-level causal similarity attention.

Reasoning:

- Auxiliary tasks are the cleanest way to use causal metadata from synthetic
  pretraining without changing inference.
- Training-time attention bias is conceptually direct, but the bias schedule
  needs care.
- Causal mask/dropout is easy to ablate and likely useful as a robustness
  method.
- Sample-level causal attention is interesting, but it introduces pairwise
  sample structure and may be more costly.

## 7. First Experimental Route

The first deeper experiment should compare:

```text
baseline TabICL-style pretraining
vs.
same budget + causal auxiliary loss
```

## 8. Screening Proxies Already Tried

The first practical screening round has now tried all four causal directions on
top of the official pretrained TabICL weights. These are proxies, not yet the
final architecture/pretraining implementation.

| Direction in Chinese | Code name | Current meaning |
| --- | --- | --- |
| 训练期特征因果偏置，推理期关闭 | `train_only_causal_feature_bias` | Add causally biased augmented context rows during fitting, but keep test/inference inputs unchanged. |
| 因果辅助任务表征代理 | `causal_auxiliary_summary_feature` | Append compact causal-role summaries, simulating representations learned by causal auxiliary heads. |
| 因果 dropout/mask 数据增强 | `causal_mask_dropout_augmentation` | Mask weak causal-proxy features more often in augmented context rows while preserving stronger causal features. |
| 样本间因果 attention 代理 | `causal_sample_attention_context` | Select context rows closest to test rows under causal-weighted sample distance, approximating sample-level causal attention. |

First 5-seed signals:

- `openml_ilpd`: strongest causal-family dataset so far. Training-only causal
  feature bias, causal auxiliary summaries, and causal mask/dropout all improve
  balanced accuracy and macro F1 repeatedly.
- `openml_credit_g`: best signal for sample-level causal attention proxy;
  `causal_sample_attention_context` improves accuracy, macro F1, and ROC AUC on
  average.
- `openml_cmc`: direct causal proxies are weaker than the earlier
  quantile/domain/probe family. CMC likely needs domain/probe structure more
  than simple causal-proxy weighting.
- Causal mask/dropout is not globally safe; it needs gating or a better causal
  role estimator before becoming a default method.

Validation-gate follow-up:

- 因果方向单次内部验证门控 `causal_validation_gated_feature` can recover small
  gains on `openml_credit_g` and balanced-accuracy/F1 gains on `openml_ilpd`,
  but it also misselects harmful causal transforms on `openml_cmc` and
  `synth_rare_boundary`.
- 因果方向多次内部验证门控 `causal_validation_gated_repeated_feature` is much safer,
  often returning identity, but it is too conservative and misses most upside.
- Median-imputing NaNs inside the cheap validation probe lets causal
  mask/dropout participate in the gate, but it does not solve the deeper
  mismatch between logistic-probe validation and TabICL's actual behavior.
- 因果方向 TabICL 单次内部验证门控 `causal_tabicl_gated_feature` improves the gate
  relative to the cheap probe: it chooses identity on `breast_cancer` and
  `synth_rare_boundary`, avoiding clear harm, and it gives repeated accuracy
  gain on `openml_ilpd`.
- However, `causal_tabicl_gated_feature` still misses much of the direct
  `causal_sample_attention_context` gain on `openml_credit_g`, and it still
  misselects harmful transforms on `openml_cmc` and `openml_kc1`.
- Therefore post-hoc validation gates are useful diagnostics, but the cleaner
  innovation path remains training-time representation shaping: causal
  auxiliary heads and/or scheduled causal attention bias.
- 不平衡诊断因果 mask 策略 `diagnostic_causal_mask_policy` is the cleanest
  safety wrapper so far: it keeps the repeated ILPD gain from causal
  mask/dropout while selecting identity on blood_transfusion, CMC, KC1,
  breast_cancer, and the rare-boundary synthetic data.
- 权重集中诊断样本因果 attention 策略 `diagnostic_sample_attention_policy` is
  safe but too conservative: it only triggers on one `openml_credit_g` seed, so
  it misses most of the direct sample-attention gain.
- 强因果权重诊断样本 attention 策略 `strong_weight_sample_attention_policy` fixes
  this first failure mode: on `openml_credit_g` it triggers sample-level causal
  attention in `5/5` seeds and recovers the direct gain, accuracy
  `0.6653 -> 0.6813` `(+0.0160)`, macro F1 `+0.0162`, ROC AUC `+0.0064`.
- 强权重诊断组合因果策略
  `strong_weight_diagnostic_causal_combo_policy` is currently the cleanest
  proxy policy: it selects causal mask/dropout on `openml_ilpd` in `5/5` seeds,
  sample-level causal attention on `openml_credit_g` in `5/5` seeds, and
  identity on `openml_cmc`, `openml_kc1`, `openml_blood_transfusion`,
  `breast_cancer`, and `synth_rare_boundary`.
- 强权重诊断组合因果策略加诊断式 balanced accuracy 阈值校准
  `strong_weight_combo_diagnostic_threshold_balanced_accuracy` is the best
  current branch when the target is balanced accuracy or macro F1: on
  `openml_ilpd` it changes balanced accuracy `0.5718 -> 0.6905` and macro F1
  `0.5697 -> 0.6626`, both positive in `5/5` seeds; on
  `openml_credit_g` it improves accuracy `0.6653 -> 0.6880`; on
  `openml_blood_transfusion` it improves balanced accuracy `0.6440 -> 0.6964`.
- The same threshold idea must be diagnostic-gated. Always-threshold variants
  hurt `openml_kc1` and `breast_cancer` in `5/5` seeds, while the diagnostic
  threshold variants disable thresholding there and return identity behavior.
- For raw accuracy on imbalanced datasets, the non-threshold strong-weight combo
  may still be preferable because thresholding buys balanced accuracy/F1 by
  spending some accuracy.
- 平方根类别先验对数校正 `class_prior_logit_adjustment_sqrt` is a promising
  lighter-weight decision/loss proxy. It improves `synth_rare_boundary`
  accuracy `0.9133 -> 0.9253`, balanced accuracy `+0.0652`, and macro F1
  `+0.0340`, with gains in `5/5` seeds for BAcc/F1. On `openml_ilpd`, it also
  improves accuracy `0.7014 -> 0.7082`, balanced accuracy `+0.0900`, and macro
  F1 `+0.0853`.
- Full 类别先验对数校正 `class_prior_logit_adjustment` is too aggressive on
  `openml_ilpd` and `openml_blood_transfusion`: it gives repeated BAcc gains,
  but spends too much raw accuracy. The square-root strength is the better
  default candidate.
- 强权重诊断组合因果策略加诊断式平方根类别先验对数校正
  `strong_weight_combo_diagnostic_prior_logit_adjustment_sqrt` is safe on
  `breast_cancer`, `openml_kc1`, and `openml_cmc` by disabling correction in
  `5/5` seeds, while keeping the imbalanced-dataset BAcc/F1 gains.
- 类别先验强度扫描 shows that the correction strength should be treated as a
  real hyperparameter. `class_prior_logit_adjustment_quarter` is the safest
  raw-accuracy setting: on `openml_blood_transfusion` mean accuracy is unchanged
  while balanced accuracy improves `+0.0211`; on `synth_rare_boundary` accuracy
  improves `0.9133 -> 0.9267`.
- 强权重诊断组合因果策略加诊断式四分之三强度类别先验对数校正
  `strong_weight_combo_diagnostic_prior_logit_adjustment_three_quarter` is the
  stronger balanced-metric setting for `openml_ilpd`: accuracy mean is unchanged,
  balanced accuracy improves `+0.1164`, and macro F1 improves `+0.0947`, both
  positive in `5/5` seeds.
- Therefore a real training objective should not hard-code one class-balance
  strength. It should schedule or learn the prior/logit correction strength
  depending on imbalance, label noise, and the target metric.
- 内部验证选择类别先验强度优化 balanced accuracy
  `class_prior_logit_validation_balanced_accuracy` confirms that adaptive
  strength selection is useful but not automatically safe. On `openml_ilpd`,
  it selects alpha `1.00` in `5/5` seeds and gives the largest balanced
  accuracy gain so far for this branch, `+0.1265`, but mean accuracy drops
  `-0.0260`.
- 强权重诊断组合因果策略加诊断式内部验证类别先验强度选择
  `strong_weight_combo_diagnostic_prior_logit_validation_balanced_accuracy`
  is safer: on `openml_ilpd` it keeps balanced accuracy `+0.0936` and macro F1
  `+0.0794` in `5/5` seeds while reducing the accuracy loss to `-0.0082`.
  On `openml_credit_g`, it keeps the causal sample-attention gain, accuracy
  `0.6653 -> 0.6813` and ROC AUC `+0.0064`.
- However, validation-selected alpha is not yet a default replacement for fixed
  alpha. On `openml_blood_transfusion`, balanced-accuracy selection improves
  BAcc/F1 in `5/5` seeds but spends `-0.0213` accuracy. Fixed alpha `0.25` is
  still the safer raw-accuracy choice there.
- This suggests a concrete pretraining design: learn or schedule the
  class-balance/causal strength with an accuracy-preservation constraint, rather
  than optimizing one inner-validation metric alone.
- The next sample-attention diagnostic can still add baseline uncertainty or
  local density, but the stronger causal-weight concentration rule is already a
  usable baseline for deciding when sample-level causal attention is worth
  enabling.

Next deeper implementation candidates:

1. Real causal auxiliary heads during synthetic pretraining.
2. Real training-time `lambda * M` feature attention bias with inference-time
   bias disabled or annealed to zero.
3. A TabICL-based gated causal mask/dropout policy selected by inner validation,
   rather than the current cheap logistic-probe gate.
4. Sample-level causal attention as either explicit attention bias or a
   learned/retrieval-style context selector.

Keep inference unchanged in both cases.

Suggested first auxiliary target:

```text

```

Suggested first loss:

```text

```

Then expand to:

- consequence/effect-of-`Y` label;
- ancestor-of-`Y` label;
- pairwise causal path label;
- continuous causal weight `w_i`.

- `openml_ilpd`
- `openml_credit_g`
- `openml_blood_transfusion`

## 9. Research Cautions

These ideas should be treated as hypotheses:

- Causal priors can help when the causal labels are reliable.
- Wrong or noisy causal graphs may hurt.
- Strong attention bias may over-constrain the model.
- Training-only causal bias is convenient but can create distribution mismatch.
- Auxiliary tasks are safer but may only help if they shape useful shared
  representations.

Therefore each method should be tested first with small ablations:

```text
same model size
same training budget
same evaluation datasets
single causal mechanism changed at a time
multi-seed confirmation for any promising result
```

## 7. Benchmark-Oriented Accuracy/AUC Gate

中文含义：准确率/AUC保护的内部验证集成门控。

After the CC18-small screen, the most benchmark-oriented path is no longer a
single fixed transform. The new gate uses only training data to compare:

```text
baseline_n1
ensemble_n4
strong_weight_diagnostic_causal_combo_ensemble_n4
optional wider feature+ensemble candidates
```

It chooses a non-baseline candidate only when internal validation accuracy stays
within a small guard margin and the combined score
`accuracy + 0.15 * AUC` improves. This directly targets the current priority:
classification accuracy and ROC AUC first, with balanced accuracy/F1 kept as
secondary diagnostics.
