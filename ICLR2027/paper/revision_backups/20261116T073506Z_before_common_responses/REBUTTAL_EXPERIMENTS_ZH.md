# 对审稿人 SbVz 的回应

## 第 1 部分：超出校准覆盖与构造器匹配范围的泛化

感谢您提出收益是否依赖评估条件匹配这一重要问题。我们通过以下补充实验对其进行了直接检验。

> Shortcut 扰动破坏了预测能力最强的特征，而五种 Shared 分类上下文中的一种恰好直接删除了该特征。
>
> 加权策略是在与评估相同的扰动类型和强度上校准的。

**校准与构造器匹配（附录 E.3，表 22，第 39 页）。** 为直接检验这两个因素，我们在权重组件消融之外，补充了 $2\times2$ Shortcut 消融实验。我们在 B/D 中从策略校准中排除 Shortcut，在 C/D 中使用非匹配的上下文构造，各条件采用相同的可用监督信息。我们发现，C 的 Acc/AUC 为 0.71187/0.85757；即使同时缺少对应的校准覆盖和匹配构造器，D 仍达到 0.69333/0.84662，而 Base 为 0.51719/0.65690。

| 配置 | 校准包含 Shortcut | 存在匹配构造器 | Acc $\uparrow$ | AUC $\uparrow$ |
|---|---|---|---:|---:|
| Base | — | — | 0.51719 | 0.65690 |
| A | 是 | 是 | **0.74394** | **0.87909** |
| B | 否 | 是 | 0.70777 | 0.85370 |
| C | 是 | 否 | 0.71187 | 0.85757 |
| D | 否 | 否 | 0.69333 | 0.84662 |

我们认为，这些结果直接回应了您关于**构造器匹配**和**同类型扰动校准**的两个疑虑：**C/D 在不使用匹配的特征删除构造器时仍优于 Base**，说明收益不局限于扰动与修复分支的直接配对；**B/D 在校准中排除 Shortcut 后仍优于 Base**，结合下文六种未参与校准的新机制上的结果，说明**学习到的加权策略能够迁移到校准未见的机制**。

> Specific 版本甚至被告知了当前出现的是哪一种扰动。

**Specific 与 Shared。** 我们希望说明两个版本所对应的不同部署场景。我们设计 Specific，是为了在机制知识可获得时，利用这些知识构造反映问题结构的额外上下文。[SPN（Lv 等，ICML 2026）](https://proceedings.mlr.press/v306/lv26g.html) [1] 同样采用面向具体问题的上下文构造，针对策略性特征修改后的输入构造示例。同时，我们也评估了无需机制标识、使用固定构造规则的 Shared。因此，**Specific 提供了利用可用问题知识的选择，而 Shared 展示了无法获得这些知识时的表现。**我们在下文进一步验证，Shared 在三类未见扰动和三类未见偏移中也保持了良好表现，并在所有设置下优于 Base。

> TabACE 在校准阶段未见过的扰动上表现如何？

**未见机制（附录 E.4，表 23–24，第 39 页）。** 我们进一步在三类新增扰动和三类分布偏移上测试了 Shared，六种机制均未参与策略校准，也没有提供专门匹配的构造器。我们评估强度 $\{0.2,0.5,0.8,1.0\}$，并对这些强度及下表所列的数据集取平均。所有对照采用相同的可用监督信息，不使用额外的目标域标签或机制标识。

我们将三类扰动施加于源域上下文。对于特征旋转和非线性传感器变换，分类任务改变目标查询特征，回归任务改变源域上下文特征。交互依赖采样对源域完整样本行进行加权采样，并保留各行对应的标签。

| 未见机制 | 数据集数（分类/回归） | Base：Acc / AUC | Shared：Acc / AUC | Base：$R^2$ / nRMSE | Shared：$R^2$ / nRMSE |
|---|---:|---:|---:|---:|---:|
| 重尾噪声 | 64 / 35 | 0.7875 / 0.8932 | **0.8176 / 0.9068** | 0.6380 / 0.5417 | **0.6757 / 0.5161** |
| 列错位 | 72 / 35 | 0.7824 / 0.8920 | **0.8186 / 0.9100** | 0.6179 / 0.5591 | **0.6751 / 0.5170** |

## 第 3 部分：与鲁棒微调的比较及互补性

**弱点 2——推理时构造上下文，还是通过学习获得鲁棒性**

> 我也不确定为什么这些上下文操作或增强应该在推理时被硬编码，而不是通过学习获得。我认为应加入一个在具有相同扰动的上下文上进行微调的 TFM 基线，它应能够学会忽略这些扰动，并可能泛化到其他类似扰动。

**问题 2——微调后的鲁棒性与 TabACE 的额外收益**

> 在具有相同扰动的上下文上微调的 TFM，是否能够达到同样的鲁棒性？TabACE 是否仍能进一步改善其表现？

感谢您建议补充这一对照。FT（fine-tuning，微调）指使用扰动增强的训练任务更新预训练骨干模型的参数。我们使用 20% 干净训练任务和 80% 匹配扰动的训练任务，对 **TabICL-v2** 进行微调，扰动强度为 $\{0.2,0.5,0.8,1.0\}$。我们采用 AdamW 更新最后四个 ICL 模块及预测组件，通过留出的训练数据选择检查点，最终评估查询不参与训练和选择。随后，我们冻结 FT 检查点，在推理阶段应用 Shared 或 Specific，分别得到 FT+Shared 和 FT+Specific（附录 E.6，表 28，第 42 页）。

在本组对照中，所有方法采用相同的数据划分与评估查询，在相同的扰动／偏移条件和强度网格下，使用统一的评价指标进行比较。详细的补充实验配置见附录 E.6，表 28，第 42 页。

| 任务 | 方法 | Clean | 五扰动平均 | 七偏移平均 |
|---|---|---:|---:|---:|
| 分类 | Base | 0.8033 / 0.9007 | 0.4973 / 0.6729 | 0.7634 / 0.8246 |
| 分类 | Shared | 0.8058 / 0.9030 | 0.7535 / 0.8647 | 0.7708 / 0.8334 |
| 分类 | Specific | 0.8167 / 0.9157 | 0.8196 / 0.9176 | 0.7795 / 0.8462 |
| 分类 | FT | 0.7970 / 0.8998 | 0.6474 / 0.7865 | 0.7596 / 0.8272 |
| 分类 | FT+Shared | 0.7994 / 0.9019 | 0.7695 / 0.8765 | 0.7687 / 0.8374 |
| 分类 | FT+Specific | 0.8018 / 0.9020 | 0.8120 / 0.9056 | 0.7943 / 0.8525 |
| 回归 | Base | 0.7425 / 0.4803 | −1.0763 / 1.2685 | 0.2746 / 0.7288 |
| 回归 | Shared | 0.7400 / 0.4825 | 0.6733 / 0.5469 | 0.6796 / 0.5105 |
| 回归 | Specific | 0.7519 / 0.4710 | 0.7578 / 0.4659 | 0.7722 / 0.4008 |
| 回归 | FT | 0.6942 / 0.5275 | 0.6118 / 0.5901 | 0.6171 / 0.5599 |
| 回归 | FT+Shared | 0.7178 / 0.5062 | 0.7160 / 0.5074 | 0.7120 / 0.4796 |
| 回归 | FT+Specific | 0.7253 / 0.4994 | 0.7421 / 0.4829 | 0.7498 / 0.4301 |

我们认同，**FT 对所测试的扰动确实有效**。同时，我们发现，**Shared 在不微调骨干的情况下，已经取得相当或更好的表现**。在 FT 上继续应用 Shared 或 Specific 能够进一步改善 FT 模型，而这些组合与直接在推理阶段使用 Shared 或 Specific 的表现总体接近。因此，我们认为这些结果回应了您的疑问：**即使可以通过扰动增强进行微调，推理时上下文构造仍有独立的应用价值**，两种方式也可以结合使用。

我们还测量了训练开销。在 **8 张 NVIDIA GeForce RTX 5090（每张 32 GB）**上，我们以每个任务使用一张卡的方式，并行完成了 175 个“数据集—评估方向”的微调任务。最终选中模型的训练运行平均耗时约 **41.4 秒/模型**；已记录的全部候选训练累计耗时约 **147.8 GPU 分钟**，这是各卡训练时间之和，而非实际经过的墙钟时间。直接在预训练骨干上应用 TabACE，可以省去这一额外的骨干优化阶段。因此，这里的计算优势是：**以更低的前置适配成本，取得总体接近的预测效果**。

作为对照，论文中 Shared 的分类和回归推理延迟中位数分别为 **872 毫秒和 141 毫秒**，对应一次 Base 和五次替代上下文前向计算。直接使用 TabACE 无需微调骨干，可省去上述训练开销。

感谢您建议进一步说明实际部署配置。**附录 B.4 已给出 Shared 注册库（表 8）、Specific 的家族定向构造器（表 9–10），以及候选选择与聚合流程（B.4.6）；附录 B.5 的表 11 汇总了实现设置。** 下面概述 TabACE 的设置。

**候选构造与选择。** 对于预先声明的家族 $z$，Specific 保留 Shared 注册库，并加入该家族对应的候选构造器：

$$
\mathcal C_{\mathrm{Specific}}(z)=\mathcal C_{\mathrm{Shared}}\cup\mathcal C_z,
\qquad R_z=|\Phi_z|,
\qquad N_{\mathrm{passes}}=1+R_z.
$$

其中，$\Phi_z$ 是在外层训练数据集上选定、并在评估留出数据集前冻结的成员列表。候选池与实际部署列表有所区别：不同覆盖范围、修复级别、特征子空间和传输级别分别定义候选，而 $R_z$ 仅统计实际部署的替代分支。

- **可用信息**：预先声明的家族 $z$、带标签源域上下文和可用的无标签目标特征；不提供目标标签或扰动强度
- **代表性家族定向候选**：Shortcut：删除强预测特征、弱特征子空间、裁剪与稳定样本筛选；Boundary：邻域标签修复与稳定子集；Domain/Covariate：目标匹配、位置尺度或分位数传输
- **选择方式**：按数据集进行五折 OOF，在其余四折上选择成员列表并拟合该家族的策略，再将二者冻结用于留出数据集
- **策略目标**：分类交叉熵、回归平方误差；校准任务覆盖强度 $\{0,0.2,0.5,0.8,1\}$
- **拟合参数**：上下文先验 $\pi_r$、证据系数 $\eta_{Q,r},\eta_{S,r}$ 和融合上限 $\alpha_{\max}$；回归另校准 $\tau_y$，并使用一致性系数

**融合策略拟合。** 公式 46 定义了在冻结骨干的前提下，对最终预测损失进行校准。参数化使用 softmax 得到归一化上下文先验，使用 softplus 保证证据系数非负、回归尺度为正，并使用 sigmoid 将 $\alpha_{\max}$ 限制在 $[0,1]$。**家族标识决定可用的候选构造库，选中的成员列表与融合策略均在留出推理前冻结。**

Shortcut 构造器匹配消融，以及附录 D.3 的均匀先验与一致性加权消融表明，**上下文构造提供有效的替代预测，学习到的可靠性先验降低不可靠分支的影响，而一致性加权优先采信当前查询下得到其他分支支持的预测**。我们已在附录 B.4.5 明确上下文类别与分支计数：Shared 在分类和回归中均使用五个替代分支加 Base；Specific 按冻结的成员列表 $\Phi_z$ 部署，替代分支数为 $R_z=|\Phi_z|$，含 Base 的总预测次数为 $1+R_z$。附录 E.5.1，第 40 页逐项列出 Folktables 的部署清单：Shared／Specific 分别使用五／八个替代分支，含 Base 共六／九次预测。主基准的候选选择流程见附录 B.4.6。

## 第 3 部分：超出扰动与构造器匹配范围的泛化

## 第 5 部分：回归共同错误与分类高置信错误

**问题——回归门控的鲁棒性**

> 由于 Ureg 随 Base 与聚合预测之间的分歧增大而增大，当替代预测与 Base 分歧最大时，更新幅度也最大。当替代预测相互相关且共同出错时，该方法会如何表现？

**问题——高置信错误下的失效**

> 在分类中，低熵但错误的 Base 预测会关闭门控，可能阻止有用的修正。这种情况发生得多频繁，又如何影响整体性能？

感谢您指出这些失效情形。我们认同，相关的替代分支可能共同出错，低熵的 Base 错误也可能抑制有效修正。我们在重建基准上量化了其发生频率与影响，并据此在保持骨干冻结的前提下改进了更新方式。

对于回归，实际更新强度为 $\alpha_i=\alpha_{\max}U_{\mathrm{reg},i}E_i$：Base 与聚合预测的分歧增大会提高 $U_{\mathrm{reg},i}$，而上下文证据也共同控制最终更新。相互一致的错误仍可能支持错误的聚合预测，因此我们进行了以下检验与改进。
