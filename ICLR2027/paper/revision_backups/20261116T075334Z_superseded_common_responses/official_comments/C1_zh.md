## Official Comment C1：超出校准覆盖与构造器匹配范围的泛化

感谢审稿人提出 TabACE 是否依赖评估机制匹配的问题。我们分别检验了**校准覆盖和构造器匹配**，并进一步评估既未参与校准、也没有专门匹配构造器的新机制。

**Shortcut 消融（附录 E.3，表 22，第 39 页）。** B/D 从策略校准中排除 Shortcut；C/D 使用非匹配构造器。各配置使用相同的可用监督信息。

| 配置 | 校准包含 Shortcut | 存在匹配构造器 | Acc $\uparrow$ | AUC $\uparrow$ |
|---|---|---|---:|---:|
| Base | — | — | 0.51719 | 0.65690 |
| A | 是 | 是 | **0.74394** | **0.87909** |
| B | 否 | 是 | 0.70777 | 0.85370 |
| C | 是 | 否 | 0.71187 | 0.85757 |
| D | 否 | 否 | 0.69333 | 0.84662 |

**C/D 在没有匹配特征删除构造器时仍优于 Base；B/D 在校准中排除 Shortcut 后仍保持收益。** 因此，这些收益能够超出直接匹配的修复分支及对该机制的校准覆盖。

**未知机制（附录 E.4，表 23–24，第 39 页）。** 我们在三种新扰动与三种新偏移上测试强度 $\{0.2,0.5,0.8,1.0\}$，对强度与所列数据集取平均。六种机制均未参与策略校准，且没有专门匹配的构造器、额外目标标签或机制标识。扰动作用于源上下文；旋转和非线性传感器变换作用于分类查询或回归源上下文特征；交互依赖采样对完整源样本行连同其标签进行重采样。

| 未见机制 | 数据集数（分类/回归） | Base：Acc / AUC | Shared：Acc / AUC | Base：$R^2$ / nRMSE | Shared：$R^2$ / nRMSE |
|---|---:|---:|---:|---:|---:|
| 重尾噪声 | 64 / 35 | 0.7875 / 0.8932 | **0.8176 / 0.9068** | 0.6380 / 0.5417 | **0.6757 / 0.5161** |
| 列错位 | 72 / 35 | 0.7824 / 0.8920 | **0.8186 / 0.9100** | 0.6179 / 0.5591 | **0.6751 / 0.5170** |
| 特征量化 | 64 / 35 | 0.7070 / 0.8782 | **0.7576 / 0.8902** | 0.3743 / 0.7070 | **0.5023 / 0.6452** |
| 特征旋转 | 31 / 31 | 0.7609 / 0.8217 | **0.7861 / 0.8420** | 0.3375 / 0.7527 | **0.4663 / 0.6810** |
| 非线性传感器变换 | 32 / 33 | 0.8002 / 0.8524 | **0.8208 / 0.8600** | 0.1009 / 0.8235 | **0.4413 / 0.6665** |
| 交互依赖采样 | 35 / 33 | 0.8214 / 0.8676 | **0.8288 / 0.8779** | 0.6487 / 0.5350 | **0.6860 / 0.5042** |

**Shared 在六种设置的全部四项指标上均优于 Base。** 这些结果直接回应了收益能否延伸至已注册校准机制和专门构造器之外的问题。

Specific 利用可用的家族知识增加问题定向上下文，这与 SPN [5] 研究的问题感知上下文构造思路一致。**Specific 提供了利用可用问题知识的选择，而 Shared 展示了无法获得这些知识时的表现。** 上述未知机制实验进一步表明，Shared 在后一种设置下仍然有效。
